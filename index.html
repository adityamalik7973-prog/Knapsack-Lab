The 0/1 Knapsack Problem

You are packing a bag that can carry a limited weight. Every item has a weight and a value. Each item is all or nothing: you take it once, or you leave it. Which items give the most total value without breaking the bag?

A tiny example

Bag capacity = 7

Item 1 · w1 · v1 Item 2 · w3 · v4 Item 3 · w4 · v5 Item 4 · w5 · v7

The shiny Item 4 alone gives 7. Item 4 + Item 1 gives 8. But Items 2 + 3 weigh exactly 3 + 4 = 7 and give 9. The best choice is not obvious, and grabbing the best-looking item first can fail.

Why not just try everything?

With n items there are 2n possible bags (each item is in or out).

Brute force explodes. DP avoids it by noticing the same sub-problems repeat.

The DP idea in one formula

Let f(i, w) = best value using only the first i items with capacity w. For item i with weight wt and value v:

f(0, w) = 0                                   (no items, no value)
f(i, w) = f(i-1, w)                           if wt > w   (item cannot fit)
f(i, w) = max( f(i-1, w),                     skip item i
               v + f(i-1, w - wt) )           take item i

Four ways to solve it (you can run all of them here)

1. Brute force

Backtracking recursion: try take / skip for every item.

Time O(2n) · Space O(n)

2. Memoization

Same recursion, but cache each f(i, w) so it is solved only once.

Time O(nW) · Space O(nW)

3. Tabulation

Bottom-up: fill the whole table row by row, then backtrack to find items.

Time O(nW) · Space O(nW)

4. Space-optimized

Keep a single row of W+1 values and loop capacity backwards.

Time O(nW) · Space O(W)

Result

    Why not greedy?

    Greedy sorts items by value/weight and takes each one that still fits. It is fast, but not always optimal for 0/1 knapsack.

    Brute force: try every combination

    For each item the tree branches: skip it (dashed grey) or take it (solid teal). A branch that would overload the bag is cut off (red ✗): that is what "backtracking" means. Every path from top to bottom is one possible bag, and the number in each circle is the bag's value so far.

    Memoization: recursion with a cache

    To answer a big question the algorithm first asks smaller ones. Each answer is saved the first time, so asking again is free. solving now waiting for a smaller answer reused from cache never needed

    Space-optimized: one array of W+1 values

    For each item, update dp[w] = max(dp[w], dp[w - wt] + v). Looping capacity backwards makes sure dp[w - wt] still belongs to the previous item, so each item is used at most once.

    Trade-off: with only one row you can read the best value, but you can no longer backtrack to list the chosen items without extra bookkeeping.
